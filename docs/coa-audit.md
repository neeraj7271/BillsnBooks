## 1. Current State of Ledger & Group Modelling

### 1.1 Database & Persistence Entities
- **`LedgerGroupOrmEntity` (`ledger_groups` table):**
  - Columns present: `id`, `tenantId`, `companyId`, `parentGroupId`, `code`, `name`, `nature` (`ASSET` | `LIABILITY` | `EQUITY` | `INCOME` | `EXPENSE`), `createdAt`, `updatedAt`.
  - **Missing Architectural Columns:**
    - `system_key`: Stable identifier (e.g. `GRP_SUNDRY_DEBTORS`) unaffected by user display renaming.
    - `is_system` & `is_locked`: Boolean protection flags preventing deletion, re-parenting, or nature modification of statutory root groups.
    - `is_active`: Soft-deactivation state.
    - `source`: Provenance tracking (`SEED`, `USER`, `TALLY_IMPORT`).
    - `seed_version`: Version tracking for additive non-destructive upgrades (e.g. `1.0.0`).
    - `report`: Target statement (`BALANCE_SHEET`, `PROFIT_AND_LOSS`, `TRADING_ACCOUNT`).
    - `affects_gross_profit`: Tally-compatible direct vs indirect operational cost distinction.
    - `normal_balance`: Normal balance side (`DEBIT` vs `CREDIT`).
    - `tally_group_name`: Exact Tally default group name for seamless XML synchronization.
    - `schedule_iii_mapping`: Companies Act Schedule III presentation classification.

- **`LedgerOrmEntity` (`ledgers` table):**
  - Columns present: `id`, `tenantId`, `companyId`, `groupId`, `code`, `name`, `currency`, `openingBalance`, `currentBalance`, `isBankOrCash`, `isActive`, `createdAt`, `updatedAt`.
  - **Missing Architectural Columns:**
    - `system_key`: Stable key for platform-essential ledgers (e.g. `LED_CASH`, `LED_PROFIT_LOSS`, `LED_OUTPUT_CGST`).
    - `is_system` & `is_locked`: Protection flags preventing deletion of critical platform accounts.
    - `source` & `seed_version`: Provenance tracking.
    - `bill_wise_tracking`: For debtor/creditor bill-by-bill settlement matching.
    - `affects_inventory`: Stock integration toggle.
    - `gst_applicable`, `gst_ledger_type` (`INPUT`, `OUTPUT`, `RCM_PAYABLE`, `RCM_INPUT`, `CASH_LEDGER`), `tax_type` (`CGST`, `SGST`, `IGST`, `CESS`, `TDS`, `TCS`).
    - `default_for`: Smart auto-fill context default tag (e.g. `SALES_INTRA`, `SALES_INTER`, `ROUND_OFF`).

## 2. Reuse of `NumberingService` & Settings Engine

- **Existing Capabilities:**
  - `NumberingService` (implemented in Slice 2) provides atomic, concurrency-safe token interpolation, starting sequences, padding, and pessimistic row-locking (`SELECT FOR UPDATE`).
  - `SettingsRegistry` (implemented in Slice 1) provides typed configuration keys, Zod validation, and hierarchical scoping.
- **Reuse Strategy:**
  - Group and ledger codes will be auto-generated by extending `NumberingService` / code resolution rather than creating a secondary ad-hoc code generator.
  - Hierarchical numeric code allocation:
    - **1000–1999:** Assets (`1000` Primary, `1100` Current Assets, `1110` Bank Accounts, `1111` HDFC Current A/c).
    - **2000–2999:** Liabilities & Equity (`2000` Primary, `2100` Current Liabilities, `2110` Duties & Taxes, `2111` Output CGST).
    - **3000–3999:** Income & Revenue (`3000` Primary, `3100` Sales Accounts, `3101` Domestic Sales).
    - **4000–4999:** Expenses (`4000` Primary, `4100` Direct Expenses, `4200` Indirect Expenses, `4201` Rent).
  - UI will display Account Name primarily, with Account Code displayed subtly as a secondary badge/metadata.

## 3. Company Creation & Accounting Mode Review

- **Current Implementation in `CompanyService`:**
  - Hard-codes 7 groups (`GRP-ASSET`, `GRP-LIAB`, `GRP-INCOME`, `GRP-EXPENSE`, `GRP-BANK`, `GRP-DEBTORS`, `GRP-CREDITORS`) and 6 ledgers (`LED-DEBTORS-DEF`, `LED-CREDITORS-DEF`, `LED-SALES`, `LED-CGST`, `LED-SGST`, `LED-IGST`) inline inside `createCompany()`.
- **Gaps:**
  - Fails to support business-type templates (Trader, Manufacturer, Service/CA, Minimal).
  - Ignores accounting mode authority:
    - **Cloud-Native:** Seeds full standard Chart of Accounts.
    - **Tally-Connected:** Must **not** overwrite Tally masters; maps Tally groups/ledgers directly to `system_key`s and offers missing standard ledgers only as suggestions.
    - **Hybrid:** Honors the designated authoritative source per entity.

## 4. Seeds, Reference Data & Tally Adapter Review

- **Current Seed Mechanism:**
  - `apps/api/src/infrastructure/persistence/seeds/seed.ts` is a monolithic dev script inserting static IDs.
  - Violates the principle: *Seed data is data, not code.*
- **Target Architecture:**
  - All standard groups and ledgers extracted into versioned, schema-validated JSON in `packages/accounting-core/seed-data/coa-v1.json`.
  - Validated by Zod in CI.
  - Idempotent `ChartOfAccountsSeeder` service executes during company creation inside the same database transaction.

## 5. Existing Hard-Coded Names & Inconsistencies

1. **Hard-coded Group & Ledger Codes:** `GRP-ASSET`, `GRP-DEBTORS`, `LED-SALES`, `LED-CGST`, `LED-SGST`, `LED-IGST` scattered across `company.service.ts`, `seed.ts`, and `invoice.service.ts`.
2. **Account Nature Inconsistencies:** `AccountNature` enum in `shared-types` has `EQUITY` and `INCOME`, but some UI files use `REVENUE`. Standardized to standard 4-pillar accounting: `ASSET`, `LIABILITY`, `INCOME`, `EXPENSE` (with Equity residing under Capital/Liabilities per Tally structure).
3. **Manual Code Entry:** UI forms force users to invent account numbers, leading to collisions and fragmentation.
